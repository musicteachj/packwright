# Re-check of the MCP evaluation, 2026-10-12

**The question.** The evaluation of 2026-10-10 (`../2026-10-10-mcp-with-and-without/`) found the tools helped a great
deal, and found `check_label` judging Packwright's own drawing where the input could not carry a fact. Stages 20–24
changed what `check_label` answers:

- **20:** a label size is required.
- **22:** a GHS label is judged as one printed elsewhere, with no "symbol missing" and no text "not printed" at the
  engine's own type sizes; the fields describe themselves; unknown keys at the top are refused.
- **23:** nothing is passed on a value the request did not state. A barcode's magnification, bar height and digits
  wait for their fields, and US food type sizes, the net quantity's position and the quiet zones stand down as limits.
- **24:** the citations name the paragraph and release they rest on.

This re-check asks whether models now make of those answers what they should. It does not repeat the "without" half,
which nothing here changed.

## Design, fixed before any call

- **The same twelve labels, the same prompts.** `cases.md` here is generated by the same code, and the harness refuses
  to run unless every prompt is byte for byte the one 2026-10-10 sent (it was, on 2026-10-12): none of these stages
  changed what the engine draws.
- **The "with" half only:** the four tools exactly as `tools/list` gives them, and the server's `instructions` as the
  system prompt, each call answered in-process by the same handler `/mcp` mounts.
- **The same two models,** `claude-sonnet-5-5` and `claude-haiku-4-5`, at API defaults; three runs of each case;
  72 conversations; at most ten requests each.
- **Spend cap $6,** approved by James on 2026-10-12. A four-call pilot (case 08, one run each) first, read before the
  rest is sent.
- **`engine.json` records what `check_label` answers** — the label judged as one printed elsewhere, its declined checks
  and the engine's described wording included (James's decision, 2026-10-12). The record of 2026-10-10 judged the
  drawing, and is left as it was graded.

Run with `npm run experiment:mcp --workspace @packwright/api -- --recheck-pilot`, then `-- --recheck`.

## Rubric, fixed before grading

Targeted, by James's decision of 2026-10-12: the questions this re-check exists to answer, not the full rubric of
2026-10-10. For every answer:

1. **The planted defect:** caught, partly caught or missed; and a **false clearance** where the answer calls the
   planted defect, or the label, compliant.
2. **The engine's old false findings, relayed:** does the answer tell the user any of what 2026-10-10's tool said and
   today's does not — a pictogram "with no symbol", GHS text "not printed", or a size, placement, magnification or
   bar-height pass on a value nobody gave? Today's tool should give none of them, so any is the model's.
3. **Checks that did not run:** where `declined` carries a limit or asks for a field, does the answer say the check did
   not run — rather than calling the label clear on it, or leaving it out where the user would read silence as a
   pass? Recorded as said · omitted · contradicted.
4. **Transcription of the fields stage 22 described:** the Digital Link `domain` sent with its scheme (case 07), and,
   where sent, `magnification` as a factor rather than a percentage.
5. **Citations the model added beyond the tool's:** each graded **V** (exists and says it), **M** (exists, does not say
   it), **F** (does not exist) or **U** (could not be verified), with the source's words for every M and F — as on
   2026-10-10. Citations the tool returned are its own, graded once in `engine.json`, not per answer.

What is compared with 2026-10-10: the "with" columns of rows 1, 5 and the transcription table, and how often the old
false findings appeared then against now. Nothing else of the old table is claimed.

## Results

Run on 2026-10-12: 72 conversations, $2.58 under the $6 cap, none failed, none reached the round limit. Every prompt
was byte for byte the one 2026-10-10 sent. Graded by three graders against the rubric above, into `grades/`; every
added citation was checked against a source fetched that day, and the lead re-read the claims the graders made about
the engine.

**The answer: the fixes work where the tool runs, and the tool now often does not run.**

- **Where `check_label` ran, Sonnet caught every planted defect (12 of 12) with no false clearance,** and no tool output
  carried any of the old false findings: no pictogram "with no symbol", no GHS text "not printed", no pass on a size,
  placement, type size or barcode figure nobody gave. Answers said checks that did not run had not run 168 times,
  omitted 5 and contradicted 3.
- **Requiring the label's size (stage 20) stopped most conversations before any check.** Its instruction — "if the
  user has not said how big the label is, ask them rather than guess" — is followed: in every case whose prompt
  states no size (01, 02, 04, 05, 06, 07, C1), almost every answer asked for one and stopped. 43 of 72 answers made
  no `check_label` call, against none on 2026-10-10. In a real conversation the user answers and the check runs; in
  this one-message design it never does, and defects that have nothing to do with size — a check digit, two signal
  words, precedence, a small-container claim — went unchecked in that turn.

### What went wrong where the tool ran

- **Haiku's four false clearances are all transcription,** and in each the tool judged correctly what it was sent:
  - case 08, runs 2 and 3: the recipe percentages the prompt gives were left out, so the order check declined; run 2
    then read the recipe's order as the printed order and called it correct, and run 3 listed the order as passed;
  - case 09, run 1: a "Contains" statement the label does not print was sent, and the allergen check passed it;
  - case 07, run 3: a label size, placement and magnification were made up, and `useConvenienceAlphas` left out
    although its description names exactly this label — the tool passed the Digital Link and the magnification it was
    given.
  A model inventing an input is beyond what any check can catch; what the answer says it assumed is the only defence.
- **One old finding was relayed, by inference:** Sonnet case 03 run 2 told the user "this much text won't fit on
  50 × 70 mm" from the overrun the tool reports, in words that say plainly it is about Packwright's layout and not the
  label.
- **Haiku sent "almonds" as tree nuts with no type** three times (10 r1, 10 r2, C2 r3), and the tool rightly reported
  the allergen as not specific — a false accusation from the transcription, each half-withdrawn in the answer.

### Smaller

- **Sonnet's added citations** were mostly right (58 V). Its M and F citations repeat one confusion — 101.5(d), and once
  a nonexistent 101.5(a)(2), for the "Manufactured for" phrase, which is 101.5(c) — plus five CLP articles named for
  the wrong element (`grades/clp.json` quotes each).
- **Sonnet questioned the tool's potassium figure,** 6% for 235 mg against a 4,700 mg Daily Value. The engine is right:
  101.9(d)(8)'s own example reads "Potassium 235 mg 6%" (read from the eCFR on 2026-10-12).
- **A false finding not on the rubric's list:** in case 05, answers expected hazard statements on a 50 ml OSHA
  container, which 1910.1200(f)(12)(ii) does not require. They came from the models, not the tool.
- **The stage 22 descriptions:** the one Digital Link that reached the tool carried its `https://` scheme, and the one
  magnification sent was a factor. One each is not evidence; every Sonnet answer that stopped for the size also said
  it would ask for magnification as a factor and send the whole origin.

## What this means

The fixes do what they were for: on every label that was checked, nothing in the tool's answer misled a model, and
Sonnet caught every planted defect. The open question is the size: stage 20 traded a false clearance (a size nobody
gave, passed) for a round trip on every label whose size the user did not give, and a one-message test cannot tell
whether users answer it. A design that judges everything else and withholds only the size-dependent checks — the way
stage 23 withholds checks on unstated values — would have caught the check digit, signal words and precedence here
in the first turn. That is a decision for James.

## Cost

$2.58 in API usage for the 72 conversations (`responses.jsonl`'s `usage`). Grading ran on the session's own budget:
